## Conclusions

1. There is **no product code** worth migrating: no ship data model, no cargo logic, no API integration, no UI beyond a placeholder navbar and three demo buttons. Deleting everything and starting a fresh SvelteKit project costs nothing.
2. What _is_ worth carrying over is **intent**: the navbar already names the first two tools (Cargo Calculator, Mining Loadout), the backend already pointed at the Star Citizen Wiki API, the abandoned `svelte_frontend` already chose SvelteKit + Tailwind + shadcn-svelte, and the infra already assumes `starculator.space` with `dev.` and `backend.` subdomains behind a Cloudflare Tunnel.
3. **Repo hygiene** to fix in the reset: untrack `vendor/`, root `node_modules/` and `nginx/html-dev/`; remove stray root `composer.*` / `package*.json`; replace `config.yml` with an example file; add a proper `.gitignore` for the new stack. Optionally rewrite history afterwards to shrink the pack (only worth it if the repo is meant to be public and cloned often).
4. **Branch state:** `claude/hopeful-babbage-7scho3` was identical to `origin/main` before this research; the reset can happen on this branch and be reviewed as one PR.
